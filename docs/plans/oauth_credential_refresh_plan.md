# OAuth Credential Refresh — Implementation Plan

Scope: backend + env-template (container SDK) + docs. **No frontend surfaces.** No migration (all new
state lives in the credential's encrypted blob; see D7). Client regeneration is still required once
(Phase 2 adds an OpenAPI route; Phase 1 adds two optional response fields).

### 0.2 Decisions (recommendation taken; alternatives one line each)
| # | Decision |
|---|----------|
| D1 | **One refresh primitive with locking**: new `OAuthRefreshService` (services/credentials/oauth_refresh_service.py). Every refresh — sync, stream, sweep, env endpoint, manual owner route — goes through `refresh_if_needed(...)`. Rejected: locking inside each caller. |
| D2 | **Lock = in-process `asyncio.Lock` per credential + `pg_try_advisory_xact_lock(ns, key32)`** on the caller's session, re-read `expires_at` after acquiring. Non-blocking try-lock on purpose: a blocking `SELECT … FOR UPDATE` in a sync Session inside an async route blocks the event loop while the holder awaits Google → same-worker deadlock. Busy → async-sleep/re-read up to 5 s, then proceed with current token. Xact lock is released by the refresh commit (no pooled-connection leak). |
| D3 | **Threshold 30 min** (`OAUTH_REFRESH_THRESHOLD_SECONDS=1800`, validated 60..2400). Google access tokens live 3600 s; 10 min let a long turn start with 11 min left and run out mid-task. 30 min + a 10-min sweep keeps any token in a running env ≥ ~20 min valid. Cost: ≤ 2 Google calls/h per credential with a running env. Must stay < token lifetime or every sync refreshes. |
| D4 | **Refresh-on-sync** via `CredentialsService.prepare_fresh_credentials_for_environment` (async) = `refresh_expiring_credentials_for_agent` then `prepare_credentials_for_environment`. Used by `sync_credentials_to_agent_environments` (after the no-running-env early return) and `_sync_dynamic_data`. **The refresh step never emits events and never calls sync** → no recursion. A refresh failure never raises out of it. |
| D5 | **Stream refresh moves into `SessionStreamProcessor._process_inner`** (single choke point for UI, channel follow-up turns, A2A, MCP). Removes the `initiate_stream` block. Closes the channel follow-up gap (message_service.py:1894) and the A2A path (a2a_request_handler.py:663) which also bypassed refresh. |
| D6 | Keep `refresh_expiring_credentials_for_agent` name/signature: `tests/utils/fixtures.py:387` patches it globally, which keeps every existing test hermetic once sync calls it. |
| D7 | **Refresh bookkeeping in the encrypted blob** (Google types): `refresh_attempted_at`, `refresh_error`, `refresh_error_kind` (`reauth_required`\|`provider_error`), `refresh_error_at`. Cleared on success; the OAuth callback rebuilds the dict (oauth_credentials_service.py:293) so re-authorization clears them. Whitelist (`AGENT_ENV_ALLOWED_FIELDS`) already keeps them out of the container. Mirrors mcp_provider `last_error`. Rejected: new columns (migration for 4 fields nobody queries). |
| D8 | `reauth_required` (no refresh_token, or Google `invalid_grant`/`unauthorized_client`) **stops automatic attempts** (sync/stream/sweep/endpoint) until re-authorization or the owner's manual refresh (`force=True`). `provider_error` (5xx/timeout/network) retries after `OAUTH_REFRESH_COOLDOWN_SECONDS` (60). |
| D9 | **Env endpoint** `POST /api/v1/agent/credentials/{credential_id}/access-token` in new `api/routes/agent_env_credentials.py`, tag `agent-credentials`, `AgentEnvContextDep`. Path mirrors `/agent/tasks/*` (task_agent_api.py). **Stays in OpenAPI** like agent-tasks/security-events (docs route-citation check needs it); client regen adds an unused `AgentCredentialsService`. |
| D10 | Endpoint scope = **Google OAuth types only**. mcp_provider tokens never live in credentials.json (they go to the SDK MCP config via `set_mcp_servers`), so there is nothing for a script to fetch; they are covered by refresh-on-sync + sweep. Linked mcp_provider/other → 422 `not_refreshable`. |
| D11 | Endpoint pushes the refreshed payload **synchronously to ctx.agent's running envs before responding** (so env-core `credential_guard` knows the new value and redacts it if a script prints it). Other agents sharing the credential are left to their own sync/sweep — Google does not revoke the previous access token on refresh. |
| D12 | **SDK calls the backend directly** from `core.cinna_api.credentials` with `BACKEND_URL` + `AGENT_AUTH_TOKEN` + `ENV_ID`. Verified: scripts inherit the env-core process env (opencode_sdk_adapter.py:285 `**os.environ`; Claude SDK inherits by default). Stdlib `urllib` only (module must import without `requests`). Rejected: env-core localhost proxy (still needs the same token; extra hop). |
| D13 | env-core writes credentials.json **atomically** (tmp + `os.replace`) — pushes become frequent and the SDK re-reads on every call; a torn read today is possible (agent_env_service.py:305-307). |
| D14 | Sweep uses `app.core.db.leader_session(lock_key)` (core/db.py:37) — pinned connection, per-credential commits safe. Not `model_discovery_scheduler`'s pattern. Never started under `settings.TESTING`. |
| D15 | Concurrency between an owner's credential **edit** and a refresh (update_credential carry-forward, credentials_service.py:1880-1892, could write back a pre-rotation refresh_token) — **not fixed here**; listed as R2. |

## §1 Phase 1 — Refresh primitive and refresh-on-sync

### 1.1 config (`backend/app/core/config.py`, next to MODEL_DISCOVERY_* ~line 939)
```
OAUTH_REFRESH_THRESHOLD_SECONDS: int = 1800      # validator: 60 <= v <= 2400
OAUTH_REFRESH_COOLDOWN_SECONDS: int = 60         # min gap between Google calls per credential after a provider_error / attempt
OAUTH_ON_DEMAND_MAX_MIN_TTL_SECONDS: int = 1800  # clamp for the env endpoint's min_ttl
```
(Sweep settings land in Phase 4.)

### 1.2 `OAuthCredentialsService` (oauth_credentials_service.py)
- Extract the Google HTTP exchange from `refresh_oauth_token` (:382, body :404-470) into
  `async _exchange_refresh_token(refresh_token: str) -> dict` (the test seam; 10 s httpx timeout).
  It raises a new `OAuthRefreshError(kind, message)` (same module): `reauth_required` on HTTP 400/401
  with `error in {invalid_grant, unauthorized_client}` or missing refresh_token; `provider_error`
  on other non-200, timeouts, network errors, missing `access_token` in the body;
  `not_configured` when `settings.google_oauth_enabled` is false. Never put token values in messages.
- `apply_token_response(credential_data, token_data) -> dict`: sets access_token, expires_at
  (now + expires_in, default 3600), rotated refresh_token if present; pops the D7 error fields.
- `refresh_oauth_token(session, credential)` keeps its signature for the manual route; it now calls
  `OAuthRefreshService.refresh_if_needed(..., force=True)` and maps errors to the **existing**
  HTTPExceptions (501 not configured, 400 otherwise) so current behaviour/tests hold.

### 1.3 `OAuthRefreshService` (new, services/credentials/oauth_refresh_service.py)
```
@dataclass RefreshOutcome:
    status: Literal["fresh", "refreshed", "busy", "cooldown", "failed", "skipped"]
    credential: Credential
    error_kind: str | None      # reauth_required | provider_error | not_configured
    error: str | None

async def refresh_if_needed(session, credential, *, min_valid_seconds: int,
                            force: bool = False, raise_on_error: bool = False) -> RefreshOutcome
```
Algorithm (Google OAuth types; mcp_provider branch in 1.4):
1. Decrypt; if `expires_at - now > min_valid_seconds` and not `force` → `fresh` (no lock taken).
2. If not force: `refresh_error_kind == reauth_required` → `failed`; last attempt (`refresh_attempted_at`)
   within cooldown and it failed → `cooldown`.
3. `async with _credential_lock(credential.id)` (bounded dict, copy `get_session_lock` eviction from
   stream_processor.py:42).
4. `SELECT pg_try_advisory_xact_lock(:ns, :key)` — `ns = 0x4F415554`, `key = int.from_bytes(id.bytes[:4], "big", signed=True)`.
   Not acquired → loop `await asyncio.sleep(0.25)` + `session.refresh(credential)` + re-check step 1, max 5 s;
   then `busy` (caller uses the current token).
5. Acquired → `session.refresh(credential)` and **re-check step 1** (another worker may have just refreshed);
   if fresh → `session.commit()` (releases the lock) → `fresh`.
6. Stamp `refresh_attempted_at`; call `_exchange_refresh_token`; on success `apply_token_response`,
   encrypt, `session.add`, `session.commit()` → `refreshed`. On `OAuthRefreshError` record D7 fields,
   commit, log (warning for reauth, error for provider) → `failed` (or raise if `raise_on_error`).
Invariants: no event emission; no sync call; refresh_token never logged/returned; one commit per path.

## §2 Phase 2 — Env endpoint

File `backend/app/api/routes/agent_env_credentials.py` (module docstring in task_agent_api.py style:
auth, scope model, route list), `router = APIRouter(tags=["agent-credentials"])`, registered in
`api/main.py` next to `task_agent_api` (:161). Route stays in schema (D9).

```
POST /api/v1/agent/credentials/{credential_id}/access-token
Auth: AgentEnvContextDep (Bearer AGENT_AUTH_TOKEN + X-Agent-Env-Id)
Body  AgentCredentialAccessTokenRequest  { min_ttl: int = 300 }   # clamp to [0, OAUTH_ON_DEMAND_MAX_MIN_TTL_SECONDS]
200   AgentCredentialAccessTokenResponse { access_token: str, token_type: str, expires_at: int, refreshed: bool }
```
Models in `backend/app/models/credentials/credential.py` (re-export in models/__init__.py). Logic in a
service method `OAuthRefreshService.access_token_for_env(session, ctx, credential_id, min_ttl)`; route
only maps `AgentEnvTokenError(code, status)` to `HTTPException(status, detail={"code", "message"})`.

| Status | code | When |
|---|---|---|
| 404 | `credential_not_linked` | no `AgentCredentialLink(agent_id=ctx.agent.id, credential_id)` (also nonexistent id — no existence leak). Same link set as `get_agent_credentials` (:2530), shared creds included. |
| 422 | `not_refreshable` | linked but type not in `OAUTH_CREDENTIAL_TYPES` (mcp_provider etc., D10) or placeholder |
| 409 | `reauthorization_required` | outcome `failed`/`reauth_required` (incl. no refresh_token) |
| 502 | `provider_error` | outcome `failed`/`provider_error`, or `cooldown` with a token already expired; `Retry-After: <cooldown left>` |
| 503 | `oauth_not_configured` | backend has no Google client config |

Behaviour: `refresh_if_needed(min_valid_seconds=min_ttl)`. `fresh`/`busy`/`cooldown` with a
still-valid token → 200 with current token, `refreshed=false`. `refreshed` → push to ctx.agent's
running envs **awaited** before responding: new `CredentialsService.sync_credentials_to_agent_environments(session, ctx.agent.id)`
(it re-runs refresh → no-op). Push failure → log, still 200 (token is valid; file catches up on next sync).
Never include refresh_token or D7 fields. Log credential id + outcome only.

After merge: `source ./backend/.venv/bin/activate && make gen-client`; commit the generated diff, no hand edits.
